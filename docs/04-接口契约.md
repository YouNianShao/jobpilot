# 04 · 接口契约

后端：FastAPI（自动生成 `/docs` OpenAPI 文档）。前端只通过下列接口访问数据。

> **只接受本机访问**：所有请求的 `Host` 必须是 `127.0.0.1` / `localhost` / `[::1]`，写操作（POST 等）带 `Origin` 时也必须是本机页面，否则 403。命令行脚本不带 `Origin`，不受影响。原因见 [06-风控与安全](06-风控与安全.md) 第 6 节。
>
> **和代码保持一致是硬要求**：这份文档曾经写着 `/api/tasks/{id}/stop`、`/api/jobs/{id}/greeting`
> 这类并不存在的接口。前端改完后端没跟上时，先改这里，再改前端。

## 1. 状态

`GET /api/status` —— 前端每 2 秒轮询一次（页面隐藏时降到 15 秒，但仍算心跳）。

```json
{
  "running": false,
  "paused": false,
  "task": {"id": "df88f72d", "mode": "full", "platform": "boss", "status": "running",
           "progress": {"current": 3, "total": 10, "label": "资深数据分析师@柯莱特"},
           "logs": ["…"], "error": "", "started_at": "2026-10-10 20:02:44", "finished_at": ""},
  "platforms": {
    "boss": {
      "name": "BOSS直聘",
      "capabilities": ["collect"],
      "remaining": {"collect_search": 40, "collect_detail": 200, "apply": 30, "monitor": 30, "daily_limit": 30},
      "limits": {"collect_search": 40, "collect_detail": 200, "apply": 30, "monitor": 30, "total": 300,
                 "per_10min": 8, "per_hour": 30, "daily_limit": 30, "risk_lock_minutes": 60, "multiplier": 2.0},
      "rate": {"per_10min": {"used": 0, "limit": 8, "remaining": 8},
               "per_hour": {"used": 0, "limit": 30, "remaining": 30}},
      "next_open_in": 0.0
    }
  },
  "locks": {"boss": {"kind": "rate_limit", "reason": "操作过于频繁", "remaining_minutes": 42}},
  "applied_today": 0,
  "daily_limit": 30,
  "counts": {"new": 0, "pending_confirm": 3, "approved": 0, "applied": 1},
  "pending_confirm": [{"id": "boss-abc123", "title": "…", "company": "…", "score": 88,
                      "platform": "boss", "salary": "…", "greeting": "…", "url": "…"}],
  "history": [{"id": "…", "mode": "collect", "platform": "boss", "status": "stopped",
               "created_at": "…", "finished_at": "…"}],
  "idle_shutdown_minutes": 2.0
}
```

- `limits` 是**该平台真正生效的上限**（已解析每平台覆盖）；界面用它当分母 —— 用全局值会让 BOSS 的额度条显示成 `40/60` 这种错的数。
- `rate` 是滚动窗口用量（近 10 分钟 / 1 小时），风控仪表上的两行就是它。

## 2. 记录

`GET /api/activity?days=7&runs_page=1&events_page=1&page_size=15` —— 记录页：用量聚合 + 任务历史 + 风控事件。任务历史和风控事件各自分页，另回 `runs_pager` / `events_pager` = `{page, pages, total, limit}`（越界页退回最后一页）；每条任务带 `summary`（人话结果）和 `not_done`，每条事件带 `label` / `text`。

```json
{
  "days": 7,
  "today": {"pages_total": 55, "pages": {"collect_search": 28, "collect_detail": 27},
            "events": {"collected": 12, "scored": 8, "greeting": 5, "applied": 2, "confirmed": 3,
                       "prefilter_rejected": 4, "risk": 0, "page_error": 0, "risk_lock": 0, "rate_stop": 0}},
  "week": {"pages_total": 554, "risk_lock": 2, "rate_stop": 1, "applied": 6, "collected": 88},
  "funnel": {"total": 4, "scored": 4, "passed": 1, "confirmed": 1, "applied": 1, "interview": 1, "offer": 0},
  "keywords": [{"keyword": "数据分析", "jobs": 6, "avg_score": 71.5, "best": 88, "passed": 3}],
  "pages_by_hour": [{"hour": "09", "count": 12}, {"hour": "10", "count": 9}],
  "pages_by_day": [{"day": "2026-10-04", "count": 42}, {"day": "2026-10-05", "count": 0}],
  "runs": [{"id": "…", "mode": "collect", "platform": "boss", "status": "stopped", "error": "",
            "created_at": "…", "finished_at": "…", "result": {"new": 12, "stopped": "…"}}],
  "events": [{"id": 41, "job_id": null, "kind": "risk_lock", "detail": "boss/captcha · 请完成验证 · 42 分钟",
              "created_at": "2026-10-07 11:05:31"}]
}
```

- `pages_by_day` 会把没有记录的日子补成 0，前端直接画。
- `funnel` 是整个岗位池的漏斗（采到 → 打过分 → 过阈值 → 确认过 → 投出去 → **面试 → offer**）；
  后两档来自 `interactions.state`（目前是手动记录，以后 HR 监测驱动会写进同一张表）。
- `GET /api/status` 的 `progress_states` 是进展状态的中文名映射，界面据此显示。
- `keywords` 按**采集时用的关键词**聚合（数据源是采集事件里的 `城市/关键词`），
  三种格式（`城市/关键词`、`关键词`、`关键词（第 N 批）`）会归一到关键词 ——
  它能回答"我这个关键词到底值不值得采"。
- `events` 只返回 `job_id IS NULL` 的**全局事件**（风控命中、速率停手、页面异常、采集/监测汇总）。风控历史必须落在这里：`locks` 表每个平台只有一行（当前锁），查不了历史。

## 3. 岗位

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/jobs?platform=&status=&limit=&offset=&deleted=` | 老格式列表（直接返回数组）；`deleted=1` 走回收站。脚本 / 冒烟测试用 |
| GET | `/api/jobs?page=1&limit=50&status=&platform=&q=&sort=&dir=&hide_nature=&deleted=` | **岗位池分页**（界面用）：筛选、搜索（标题 / 公司）、排序、计数都在库里对全量做。返回 `{items, total, page, pages, limit, counts, platform_counts}`；`counts` 是每个状态的数量（受 `q` / `platform` 影响，不受 `status` 影响）；`platform_counts` 是每个平台的数量（受 `q` / `status` / `hide_nature` 影响，不受 `platform` 影响）；`sort` ∈ `created`（默认，采集时间）/ `score` / `title` / `company` / `city` / `status`，`dir` ∈ `desc` / `asc`；`hide_nature=1` 排除外包 / 培训 / 营销话术；`page` 超过最后一页时回到最后一页；`limit` 上限 200 |
| GET | `/api/jobs/{id}` | 详情（含 events 时间线、评分依据、定制简历路径） |
| POST | `/api/jobs/confirm` | body `{platform, ids?}`；不传 ids = 该平台全部待确认 → approved；**传 ids 时不按平台过滤**（岗位池全平台混排），只确认其中 `pending_confirm` 的，其余在 `skipped: {状态: 个数}` 里返回原因 |
| POST | `/api/jobs/reject` | 同上 → rejected |
| POST | `/api/jobs/delete` | body `{ids}` → 软删除（回收站） |
| POST | `/api/jobs/restore` | body `{ids}` → 从回收站恢复 |
| POST | `/api/jobs/purge` | body `{ids}` → 彻底删除（连事件一起清） |
| POST | `/api/jobs/{id}/resume` | 生成该岗位的定制简历（防编造闸门） |
| POST | `/api/jobs/{id}/applied` | body `{note?}` 手动投递回执：状态 → applied，计入今日额度（与自动投递同一口径） |
| POST | `/api/jobs/{id}/progress` | body `{state, note?}` 记录投递之后的进展：`viewed/replied/interview/interviewed/offer/rejected` |
| POST | `/api/jobs/{id}/interview-prep` | 针对该岗位生成面试问题 + 该讲哪段经历（要求简历可读、岗位有 JD） |

## 4. 任务

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/tasks` | body `{mode, platform, limit, keywords, cities, max_pages}`（后三个是可选的本次覆盖值，界面不再传：直接用 config.yaml 里的）；mode ∈ collect/score/greet/confirm/apply/monitor/followup/full；**score / greet 的 platform 可以为空 = 所有平台**；**apply 的 platform 为空 = 所有能投的平台轮流投**（结果带 `per_platform` 和没投的平台 `skipped` / `note`）；**full 可带 `plans: [{platform, keywords, cities, max_pages}]` 和 `apply_after`**：勾选的平台按顺序依次采集（这一次的条件，不写回配置；同一平台出现两次返回 400），评分 / 招呼语对所有平台，有待确认就停，没有且 `apply_after` 才在勾选的平台里轮流投递；full 只采集指定平台，评分 / 招呼语对所有平台 |
| POST | `/api/tasks/stop` | 请求停止（软停止：做完当前动作就收手） |
| POST | `/api/tasks/pause` / `/api/tasks/resume` | 暂停 / 继续 |

> 同一时间只允许一个任务：并发开页面会把同一个账号的节奏瞬间拉满，这是风控红线。
> 已有任务在跑时再启动会返回 409。
>
> 多平台投递不是并发：一个任务里**轮流**投 —— 选最早到点的平台投一个，这个平台进入自己的投递间隔，
> 间隔里去投别的平台。每个平台的间隔 / 页面额度 / 每日上限 / 风控锁都照旧按平台算；
> 刚采集完的平台在「采集→投递」冷却里先排后面；某个平台掉登录 / 被风控 / 被闸门拒绝只停那一个。
> `/api/status` 带 `approved_by_platform`，界面据此在确认框里逐个平台写清楚要投几个。

## 5. 配置与健康

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/resume` | 简历正文 + 可用性（`ok` / `problem` / `chars` / `path`） |
| POST | `/api/resume` | body `{text}` 存进当前账号的 `resumes/master.md`（A：`data/resumes/`，B：`data/accounts/B/resumes/`）并把配置指过去（只写固定路径） |
| GET | `/api/cities?platform=` | 该平台认识哪些城市（`restricted` / `count` / `hot` / `cities`） |
| POST | `/api/suggest-keywords` | 让模型看简历 + 已采数据推荐搜索关键词（不碰浏览器；返回 `keywords` / `avoid` / 模型元信息） |
| GET | `/api/config` | 返回配置（`api_key` 掩码为 `sk-ab****wxyz` 这种：只留首尾各 4 位）；`_providers` = 服务商预设（地址 / 协议 / 推荐模型 / 去哪拿 Key），`ai.provider` 为空时按 base_url 认出 |
| POST | `/api/ai/test` | body = 配置页当前的 `ai.*`（不保存）；Key 为掩码时用已保存的 Key；发一次极小请求，返回 `{ok, model, latency_ms}` 或 `{ok:false, error, hint}` |
| POST | `/api/config` | 按 section 局部更新并保存；`api_key` 含 `*` 时忽略（防掩码覆盖）；返回 `{ok, synced}`，`synced` = 同步了共用段（AI / 风控 / 平台上限数值）的其它账号 |
| GET | `/api/accounts` | `{active, accounts:[{id, name, active, ready}], running}`；`/api/status` 里也带 `account:{id, name}` |
| POST | `/api/accounts/switch` | body `{id}`；有任务在跑返回 409，未知账号 400；成功 `{ok, active, name}`，前端随后整页刷新 |
| GET | `/api/health` | 浏览器（CDP）连通性 |
| GET | `/api/checks` | 系统体检：AI Key / 简历 / 浏览器 / 数据库 / 磁盘 / 活跃时段 / 平台配置（每项带 `level` 与 `fix`） |

## 6. 其它

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/follow-ups` | 待跟进列表（含是否 due） |
| GET | `/api/interactions` | HR 互动记录 |
| GET | `/api/export` | CSV（UTF-8 BOM）；参数 `status` / `q` / `hide_nature` / `platform` 与岗位池同一套筛选（界面上看到什么就导出什么）；平台、状态写中文 |
| GET | `/api/backup` | 下载整条流水线的 zip（库的在线一致性快照 + config.yaml + 定制简历 + manifest） |
| GET | `/` | 看板首页（静态文件） |

## 7. 约定

- 错误统一 `{"error": "..."}`；配置校验失败返回 400，冲突返回 409。
- 前端每 2 秒轮询 `/api/status`；任务进度从该接口读，不做 SSE/WebSocket（本地单人不需要）。
- 记录页是聚合查询，轮询节流到 15 秒，不与心跳同频。
