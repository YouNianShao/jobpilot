# 02 · 架构设计

> 这份文档跟着代码走。**凡是和代码不一致的，以代码为准，并回来改文档。**

## 1. 分层

```
┌──────────────────────────────────────────────────────────────────────┐
│ 入口层   CLI (cli.py)          Web API (web/app.py, FastAPI)          │
├──────────────────────────────────────────────────────────────────────┤
│ 任务层   tasks.py（单任务互斥 · 暂停/停止 · 进度与日志 → task_runs）    │
├──────────────────────────────────────────────────────────────────────┤
│ 服务层   collector · scorer · greeter · confirmer · applier · followup │
│          resume · monitor · keywords · interview · progress · probe    │
│          health · backup · orchestrator      ← 不含任何平台细节         │
├──────────────────────────────────────────────────────────────────────┤
│ 驱动层   PlatformDriver 协议 + registry + 四个平台实现                  │
│          BrowserDriver 协议（真实 = patchright / 测试 = FakeBrowser）   │
├──────────────────────────────────────────────────────────────────────┤
│ ★ 安全内核 safety/policy.py —— 所有副作用的唯一闸门（见第 3 节）        │
├──────────────────────────────────────────────────────────────────────┤
│ 横切     db(sqlite+版本化迁移) · config · models · nature · ai/          │
└──────────────────────────────────────────────────────────────────────┘
```

## 2. 两个关键协议

### 2.1 BrowserDriver（浏览器）

```
open(url) -> Page
Page.goto(url) / Page.text() / Page.html() / Page.url / Page.title
Page.locator(selector) -> Locator（自动等待）
Page.click(selector) / Page.fill(selector, text) / Page.press(...)
Page.eval(js) -> Any        # 只在没有 locator 方案时用
Page.screenshot(path) / Page.close()
```

- 真实实现：`browser/patchright_driver.py`，`connect_over_cdp(cdp_url)` 连**用户自己已登录**的 Chrome
- 测试实现：`browser/fake.py`，按脚本返回预置页面；`FakeBrowser.open()` **按 URL 匹配**（不是按顺序）

### 2.2 PlatformDriver（平台）

```
key / name / capabilities: frozenset[str]
supported_cities / hot_cities        # 受限平台的城市表（界面据此提示与校验）
collect(ctx: DriverContext) -> CollectResult
apply(ctx: DriverContext, job) -> ApplyResult      # 未核验的平台返回 unsupported
monitor(ctx: DriverContext) -> MonitorResult
probe_apply?(ctx, job) -> dict                     # 可选：只"看"不"发"的投递预演
```

`DriverContext` 是驱动能拿到的**全部**：`config / repo / browser / policy / stop / platform / log / progress`。
驱动不能自己开页面 —— 必须 `ctx.reserve(stage)` 过安全内核；也不能自己读简历 —— 用 `ctx.resume_text()`。

## 3. ★ 安全内核（唯一闸门）

任何会改变外部世界的动作（开页面 / 投递 / 发消息）**只能**通过 `Policy.authorize(action)` 获得许可。
闸门顺序（fail-closed）：

```
authorize(action)
 ├─ 0. 平台冷却锁      命中验证码/限流/封禁 → 该平台整体拒绝（按平台隔离）
 ├─ 1. 发送时间窗      仅 apply/send
 ├─ 2. 随机休息日      仅 apply/send
 ├─ 3. 每日投递上限    apply_one
 ├─ 4. 采集→投递冷却    apply_one：刚采完不能马上发
 ├─ 5. 活跃时段        page_open：不在 active_windows 内 → 拒绝
 ├─ 6. 滚动速率窗口    page_open：10 分钟 / 1 小时上限；能等就等，等太久 → 拒绝
 ├─ 7. 页面预算        page_open：按 平台+阶段+本地日期 计数
 ├─ 8. 开页面节流      page_open：两次开页面之间强制随机间隔（可被停止打断）
 └─ 9. 放行            记账 → Permit（附剩余额度与等待时长）
```

命中风控后除了冷却锁，还会写一段**降速期**（默认 24 小时内开页面间隔 ×2）：
会出验证码说明节奏已经踩线，原样恢复等于再踩一次。详见 [06-风控与安全](06-风控与安全.md)。

## 4. 数据流

```
采集   collector → driver.collect → 过闸门开页面 → db.jobs(new) + events(collected)
评分   scorer    → 预筛（实习/黑名单/薪资/岗位性质）→ AI → db.jobs(filtered|pending_confirm)
招呼语 greeter   → AI（需要简历）→ db.jobs.greeting
确认   confirmer → db.jobs(approved|rejected)
投递   applier   → 过闸门 → driver.apply → db.jobs(applied/…) + events
手动回执 mark_applied → 同一条 applied 事件口径（也占每日额度）
监测   monitor   → driver.monitor（未核验）→ db.interactions
进展   progress  → 手动记录 viewed/replied/interview/interviewed/offer/rejected
简历   resume    → AI 重组（防编造闸门）→ 落盘 Markdown + db.jobs.resume_path
跟进   followup  → 纯文本生成，不碰浏览器
建议   keywords  → AI 读简历 + 已采数据的实际效果 → 推荐搜索词
面试   interview → AI 读简历 + JD → 预测问题 + "该讲哪段经历"
```

## 5. 任务模型

- 进程内**单任务互斥**：同时只跑一个任务（并发开页面会把账号节奏瞬间拉满）
- 启动前先过**能力门** `check_mode()`：这个模式在当前配置/驱动下做不了事就直接拒绝并说明原因
- API：`POST /api/tasks` 启动 · `POST /api/tasks/stop|pause|resume` · 进度与日志读 `GET /api/status`
- 停止是**协作式**的：服务在安全点调用 `ctx.stop.check()`；节流等待走 `stop.sleep`，所以"停止"能
  立刻打断正在进行的等待（实测 1 秒生效）
- **任务日志是给人看的**：驱动里的 `[boss]` `[safety]` 前缀由 `tasks.humanize()` 换成「BOSS直聘：」「风控：」，参数写成「关键词 … · 城市 … · 每个组合翻 N 页」，不打印 dict；结束时补一句结论（「采集结束：新增 20 个岗位…」）
- 服务层**返回** error 的情况（被风控锁 / 没登录 / 闸门拒绝）状态仍是 completed，但 `task.error` 会写上可读原因，界面显示「没有做成」而不是绿色的「已完成」；历史行用 `run_problem()` 从旧记录的 result 里补出原因
- 抛异常失败时，traceback 写进 `data/serve.log`（stderr），任务日志只留一句中文；`task_runs.error` 保留异常原文

## 6. 目录与职责

| 路径 | 职责 |
|---|---|
| `config.py` | 配置模型（pydantic）+ 加载/保存；平台段支持"只写要覆盖的键" |
| `models.py` | 领域模型：Job / Status / CollectResult / ApplyResult … |
| `db.py` | 连接（WAL）、查询、写入、**版本化迁移**（`_MIGRATIONS`） |
| `nature.py` | 岗位性质识别（外包/培训/营销话术），纯规则、不调 AI |
| `browser/` | BrowserDriver 协议 + patchright 实现 + 假实现 |
| `platforms/` | PlatformDriver 协议 + registry + 四平台驱动 + 城市表 |
| `safety/` | **policy（唯一闸门）** · budget · locks · throttle · risk |
| `services/` | 业务服务（不含平台细节），见第 1 节列表 |
| `ai/` | LLM 客户端 + **版本化提示词**（`prompts/*.v1.md`） |
| `web/app.py` | FastAPI 路由；`web/static/` 前端（原生 ES Modules，无构建） |
| `cli.py` | 命令行入口（含 `jobpilot check` 体检） |
| `tools/` | 开发工具：check_ui / smoke_e2e / shots / 平台探针 / 城市表刷新 |

## 7. 关键设计决策

| 决策 | 理由 |
|---|---|
| **副作用必须过唯一闸门** | 风控不是"某个模块"，而是所有动作的通道；驱动拿不到"直接开页面"的能力 |
| **AI 只做判断，控制流是代码** | 评分/话术/建议让模型做；限额、顺序、停止、状态流转永远由确定性代码决定 |
| **能力集只声明已核验的动作** | 界面上有按钮但一点就失败，比没有按钮更糟；四个平台目前都只声明 `collect` |
| 驱动协议而非 if-else | 加平台只写新文件，服务层零改动；测试可以塞假驱动 |
| 页面预算/速率放 safety 而非驱动 | 防封号是**账号级**约束，必须统一计数 |
| 冷却锁、速率窗口、降速都按平台 | 一个平台出问题不该连坐其它平台 |
| 人工确认默认开启 | 投递是唯一不可逆动作 |
| 先做"人工记录进展"再等监测驱动 | 驱动未核验不等于这件事没法用；人工记录和将来的驱动写同一张表 |
| 前端不引入构建 | 单人项目，原生 ES Modules 足够；构建链是纯负担 |
| SQLite 不引 ORM | 表少、查询简单；ORM 只会增加理解和升级成本 |

## 8. 前端设计系统（2026-10-11 重构）

前端保持**原生 ES Modules，无构建步骤**：一个 index.html + app.css + 若干 js 模块（见 8.1 的文件表）。
不引入 React/Vite 是刻意的 —— 看板要能用 `python -m jobpilot.cli serve` 直接跑起来，
不要求任何人先 `npm install`。代价是样式与组件要靠纪律维持，所以把规则写死在这里。

### 8.1 三层结构

| 层 | 文件 | 只负责 |
|---|---|---|
| 设计令牌 | `app.css` 第 1 节 `:root` / `[data-theme=light]` | 颜色、圆角、间距、阴影、缓动、字体栈。**组件里不写死颜色** |
| 组件样式 | `app.css` 第 6–20 节 | 按钮 / 卡片 / KPI / 风控卡 / 表格 / 抽屉 / 提示 |
| 外壳 | `js/app.js` | 视图切换、轮询、顶栏、概览 / 监测 / 记录 / 详情抽屉 / 跑任务（`runTask`：直接按已保存的配置跑，只有投递先确认） |
| 共享 | `js/store.js` · `js/common.js` · `js/ui.js` · `js/api.js` | 全局状态（`state` / `$`）· 状态中文名等常量 · 通用 UI 原语 · 请求 |
| 视图 | `js/views/jobs.js` | 岗位池（服务端分页 / 筛选 / 勾选） |
| 视图 | `js/views/config/` | 配置页：`index.js` 主流程 · `fields.js` 字段清单 + 校验 · `resume.js` 简历分组 · `city-picker.js` 城市选择器。**第一次打开配置页时才加载** |

### 8.2 必须守住的约定

- **视图不 import app.js**：要用的共用动作（刷新、打开详情、切平台…）由 `initJobs(ctx)` / `initConfig(ctx)` 传进来，
  否则 app.js ↔ 视图会循环依赖。多个视图都要读的东西放 `store.js`，某个视图自己的状态留在自己的文件里。
- **懒加载的边界**：静态 import 的模块（app / store / ui / api / common / views/jobs）里任何一处语法错误
  都会让整页打不开；配置页是动态 `import()` 的，它坏了只有配置页显示「配置页没能加载」，其余视图照常。
- **id 是接口**：`check_ui.py` 和各视图都按 id 取节点，改样式不要动 id；
  新增视图要同时改 `.nav-item[data-view]` 和 `.view[data-view]`（自检会逐个点开验）。
- **状态色只用语义令牌**：`--ok / --warn / --bad / --accent`。同一个词色在风控、状态、徽章里保持一致。
- **危险数字一眼可读**：额度、冷却、上限一律用 `.meter` + `remainTone()`，剩得越少越红。
- **不是每个数字都值得一块卡**：风控面板从「每平台 6 条进度条」改成「一行结论 + 三格关键数字 + 点击展开」，
  因为概览要回答的是「现在能不能干活」，不是「给我看 36 个进度条」。

### 8.3 怎么验

| 手段 | 命令 | 验什么 |
|---|---|---|
| 前端自检 | `python tools\check_ui.py` | 真机加载页面、抓 JS 异常、逐个点开 5 个视图确认没渲染成空白 |
| 端到端 | `python tools\smoke_e2e.py` | 34 项：能力门 / 合成岗位 / 真实模型调用 / 回收站 / 暂停停止 |
| 驱动页面 | `tools/cdp.mjs click <id> <sel> [i]` / `text <id> <sel> [i]` | 按选择器点一下 / 读文本，用来验交互（比写一堆一次性 JS 探针稳） |
| 临时浏览器 | `powershell -File tools\ui_chrome.ps1` / `-Stop` | 起停一个独立 profile 的 Chrome（9333）：UI 迭代不该拿用户那个带登录态的调试 Chrome 当试验场 |
| 截图 | `tools/cdp.mjs shot <id> <png> <w> <h>` | 目视核对。UI 迭代不需要登录态，可以起一个**独立临时 Chrome**（`--user-data-dir` 指向临时目录）来截图 |

> 踩坑一：临时 Chrome 用完要按 `--user-data-dir` 精确关掉，别影响用户自己的调试 Chrome（账号 A 9333 / 账号 B 9334）；
> 起停直接用 `tools\ui_chrome.ps1`（`-Stop` 关闭），不要再手写那串参数。
>
> 踩坑二：**静态资源必须带 `Cache-Control: no-cache`**（app.py 的中间件）。不设的话浏览器会按
> 「启发式新鲜度」缓存 app.css / app.js —— 改完样式重新开页面还是旧的（真踩过：命令面板的样式改了，
> 眼睛看到的却是缓存）。no-cache 是「每次校验」不是「不缓存」，没变就是 304，代价极小。
>
> 踩坑三：`.card` 用 `overflow: clip` 而不是 `hidden` —— `hidden` 会让卡内的 `position: sticky` 失效，
> 配置页左侧那根吸顶导航就靠它。clip 裁剪效果一样，但不建立滚动容器。
> 另外 `PatchrightBrowser.health()` 现在只打 `/json/version`（2 秒超时），不再真的 `connect_over_cdp` ——
> 后者在浏览器状态异常时会卡几十秒，把「浏览器没连上」表现成「接口卡死」。
