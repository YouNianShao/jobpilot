# 07 · 开发与验收

## 1. 环境

- Windows + Python 3.11+（本机 3.13 可用）
- 用户已登录的 Chrome，开启远程调试：
  `chrome.exe --remote-debugging-port=9223 --user-data-dir=E:\JobPilot2\chrome-profile`

## 2. 安装与运行

```bash
cd E:\JobPilot2
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
copy config.example.yaml config.yaml      # 填 api_key / 关键词 / 城市
jobpilot serve                            # 启动服务（默认 http://127.0.0.1:8700）
jobpilot --mode collect --platform 51job  # 或直接用 CLI
```

## 2.1 启动链的编码契约（踩过坑，别改坏）

`启动 JobPilot.lnk → launch.vbs → start.bat → tools\launch.ps1`

- **`start.bat` 必须保持纯 ASCII**：cmd 按 OEM 代码页解码 .bat，中文注释会被误解码成命令；
  在快捷方式的隐藏窗口里这会**吃掉后面的行**，表现是"双击没反应"，而直接跑 bat 却正常。
  中文提示一律放在 `launch.ps1`（UTF-8 **带 BOM**，Windows PowerShell 5.1 才不会乱码）。
- 这两条都有回归测试守着：`tests/test_launcher.py`。
- 启动失败时 `launch.ps1` 会把真实错误写进 `data\launch-failed.txt` 并自动打开 —— 静默失败不许再发生。

## 2.2 静态检查（ruff）

```bash
ruff check .          # 未定义名 / 未使用导入 / 导入顺序 / 过时写法 / 可疑写法
```

规则在 `pyproject.toml` 的 `[tool.ruff.lint]`：选 `E,F,W,I,UP,B`，忽略 `E501`（长行交给编辑器）
和 `UP042`（`Status` 故意同时继承 `str+Enum`，换 `StrEnum` 会改 `str()` 的行为）。

为什么值得跑：这一轮第一次跑就抓出 8 个没用到的导入、1 个被重复导入的名字、
5 处没写 `r""` 的正则/路径字符串（Python 3.12 起会告警）—— 都是长期小改动攒出来的。
现在它是**零告警**状态，改动前先跑一遍。

## 3. 测试策略（关键）

**用假浏览器测 90% 的逻辑，不需要 Chrome。**

- `browser/fake.py` 提供 `FakePage`：按预置的 HTML/JSON 返回 `text()/eval()/locator()`
- `tests/fakes.py` 提供 `FakeDriver`：按脚本返回 `collect/apply/monitor` 结果
- 因此下面这些都能在 CI/本地秒级跑完：
  - 状态机流转（new → pending_confirm → approved → applied）
  - 人工确认门（开启/关闭两种行为）
  - 页面预算与冷却锁（含"超限当天停止""按平台隔离"）
  - 跨平台去重
  - 配置校验、去重归一化、任务停止

```bash
pytest -q
```

覆盖率目标：非浏览器代码 ≥ 80%。

### 3.1 三层验证，缺一层都会漏 bug

只跑 pytest 是不够的 —— 这一条是用一次真实故障换来的：**仪表盘的"评分"按钮曾经是坏的**
（前端不带 `limit` → `options.get("limit", 100)` 在"键存在但值为 None"时拿到 `None`
→ SQL 的 `LIMIT ?` 绑 `None` → `sqlite3.IntegrityError: datatype mismatch`），
而 129 个单元测试全绿，因为测试用例都显式传了 `limit`，恰好绕开了界面那条路。

| 层 | 工具 | 覆盖什么 | 什么时候跑 |
|---|---|---|---|
| 单元 | `pytest` | 纯逻辑、假浏览器、状态机 | 每次改代码 |
| 前端 | `python tools\check_ui.py` | 真加载页面、抓 JS 异常、**逐个点开五个视图并确认都渲染出内容** | 每次改前端 |
| 端到端 | `python tools\smoke_e2e.py` | **HTTP 打真接口**，走界面那条路（不带可选参数）、真的调用模型 | 每轮收尾 / 发版前 |
| 入口 | `python tools\smoke_e2e.py --via-shortcut` | 先从**桌面快捷方式**重启看板，再跑上面那套 —— 启动链断了也能发现 | 改过启动脚本后 / 发版前 |

> 为什么单列"入口"这一层：前三层全是直连服务，**没有一层会碰桌面快捷方式**。
> 于是"双击没反应"这种对用户等于项目全挂的故障，它们在设计上就看不见 —— 这已经真的发生过一次。

`smoke_e2e.py` 会造一个合成岗位跑完整个生命周期（招呼语 → 确认 → 手动投递回执 → 跟进 →
定制简历 → 导出 → 回收站 → 彻底删除），结束时把合成数据清干净；真实岗位不受影响。
它要求看板正在运行。

## 3.2 先体检，再动手

任何"跑了没反应"的排查，第一步都是 `jobpilot check`（或顶栏「体检」）。它会明确告诉你
是浏览器没连上、简历路径失效、AI Key 没配，还是只是不在活跃时段 —— 而不是让你去翻日志。

## 4. 平台实机验收清单（每个平台一份）

> 投递类能力的验收**先从预演开始**：`POST /api/jobs/{id}/probe-apply` 只打开岗位页看按钮，
> 不点不发（走采集详情页同一条额度与闸门）。预演通过 = 结构可用；真正开放自动投递
> 还需要用户明确同意"让程序替你发消息"。

新写或改动平台驱动后，**必须在真实登录环境逐项确认并勾选**：

- [ ] 采集：搜索页能出结果，标题/公司/薪资/城市/id 都正确
- [ ] 采集：翻页正常，末页能识别（不是把失败当结束）
- [ ] 采集：跨平台重复岗位被去重
- [ ] 投递：能找到并点到投递按钮
- [ ] 投递：结果弹窗被正确识别（成功 / 已投 / 需简历 / 需登录）
- [ ] 投递：页面预算与冷却锁生效（可用假数据演练）
- [ ] 监测：能抓到已投递状态并识别 HR 事件
- [ ] 风控：验证码/限流页面能触发停止 + 冷却锁

未通过验收的动作，**不要在 `capabilities` 里声明**。

### 4.2 前端验收（每次改 CSS / js 之后）

| 步骤 | 命令 | 说明 |
|---|---|---|
| 起临时浏览器 | `powershell -File tools\ui_chrome.ps1` | 独立 profile + 9333 端口；用完 `-Stop`。**不要拿用户那个带登录态的调试 Chrome 当试验场** |
| 真机自检 | `set CDP_PORT=9333` 然后 `python tools\check_ui.py` | 真的加载页面、抓 JS 异常、逐个点开 5 个视图确认不是空白 |
| 目视核对 | `node tools/cdp.mjs shot <id> <png> 1500 1000` | 宽屏；再补一张窄屏 `620 900` |
| 端到端 | `python tools\smoke_e2e.py` | 34 项 |

**三个必须知道的坑**（都真踩过，写在这里省得再踩）：

1. **静态资源必须带 `Cache-Control: no-cache`**（app.py 里的中间件）。不设的话浏览器按启发式缓存，`app.css` 改完看到的还是旧样式 —— 会得出「改了没用」的错误结论。
2. `.card` 用 `overflow: clip` 而不是 `hidden`：后者会让卡内的 `position: sticky` 失效（配置页左侧吸顶导航就靠它）。
3. 手动 `open` 打开页面**不会**忽略缓存重载，`check_ui.py` 里的 `watch` 会。看样式时优先用自检，或先 reload 再截图。

**窄屏至少拍两张（900 / 620）**：侧栏折叠、流程带堆叠、表格横向滚动这三处最容易坏。


## 4.1 发版前：先备份你自己的数据

`GET /api/backup`（设置页有按钮）会把 **库的在线一致性快照 + config.yaml + 定制简历** 打成一个 zip。
改结构、动迁移、或者要试新东西之前，先下载一份 —— 这是唯一能整体复原的东西。
